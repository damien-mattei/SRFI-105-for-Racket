**Pragmas** (bare symbols written in the code, removed by the reader): ```BEGIN-STRICT-SRFI-105-REGION``` / ```END-STRICT-SRFI-105-REGION```, the strict mode where the reader follows SRFI 105 as the original reader (```{a + b * c}``` is ```($nfx$ a + b * c)```; ```$nfx$``` and ```$bracket-apply$``` can be taken from Scheme+ with ```(require (only-in Scheme+ $nfx$ $bracket-apply$))```), ```ANNOTATION-ON``` / ```ANNOTATION-OFF```, the type annotation pass of Scheme+, and ```CARE-OF-QUOTES-ON``` / ```CARE-OF-QUOTES-OFF```, the quoted lists as data or as infix expressions (symbolic computation). A pragma is written alone, or alone in curly brackets, inside the module form or before it (it then acts on the whole module), or alone at the REPL; it acts only on the file where it is written. See the section Pragmas of the documentation: [https://docs.racket-lang.org/SRFI-105/index.html](https://docs.racket-lang.org/SRFI-105/index.html)

Also provides the parser curly-infix2prefix4racket.rkt in src/ sub-directory:


```racket curly-infix2prefix4racket.rkt [--verbose] file2parse.rkt > parsedfile.rkt```

It writes on the standard output the Racket code that the reader gives to the compiler (the annotated code when the file has the pragma ```ANNOTATION-ON```). The option ```--verbose``` displays the banner and the state of the type annotation on the error output.


Some REPL (Read Eval Print Loop) are available in src/ subdirectory.

A Makefile is also available in the same subdirectory, to parse Scheme+ file in standart Scheme,allowing the debugging of parsed files in Racket GUI or command line.

Type annotation and inference for Scheme+ (version 18.0), shared with SRFI 110 (annot+.rkt, written in Scheme+ by bootstrapping). When the pass knows the types of the operands it replaces an overloaded, dynamically dispatched operator by a monomorphic primitive (```fl+```, ```fx*```, ...), resolves a square bracket access to the exact accessor, specializes vector and string assignments and folds constant expressions. The types are given with the ```type``` form of Scheme+, see the Scheme+ documentation (section Type annotation and inference).

The pass knows the overloads declared with ```overload-operator``` and ```overload-procedure``` of Scheme+, and those restated with ```require-overload-operator``` / ```require-overload-procedure``` for a module that imports an overloaded operator or procedure.

Composite types: ```#(T)``` is a vector whose elements have the type ```T```, ```(T)``` a list whose elements have the type ```T```. The inference knows the result of ```vector-map```, ```map```, ```apply```, ```vector->list```, ```list->vector```, ```vector```, ```list``` and specializes the procedure passed to them; a ```lambda``` passed to ```vector-map```, ```map```, ```for-each``` or ```vector-for-each``` is typed by the context (the types of the elements) or by a ```type``` annotation in its body. Example:

```scheme
ANNOTATION-ON

(define (dot-product v1 v2)
  (type #(flonum?) v1 v2)
  (apply + (vector->list (vector-map * v1 v2))))

;; code generated by the annotation parser: (apply fl+ (vector->list (vector-map fl* v1 v2)))
```

Pragmas ```ANNOTATION-ON``` and ```ANNOTATION-OFF```: they turn the pass on or off by region, on the elements that follow them in the same list (the body of the module, of a procedure, ...) and on all that is nested in them, until the other pragma or the end of the list; after the end of the list the state of before comes back. The pass is off at the beginning of each file (a pragma acts only on the file where it is written, not on the modules this file requires). The pragma can be written inside the module form or at the top level of the file (before the module form, it acts on the whole module). In a region turned off the code is not rewritten, but the overload declarations and the ```type``` forms are still taken into account. Nothing remains in the code: the annotation pass removes the pragmas.

The local variables of ```let```, ```let*```, ```letrec```, ```letrec*```, named ```let```, ```let-values``` and ```let*-values``` hide the type of an outer variable of the same name, as the parameters do: Scheme code keeps its meaning in a region ```ANNOTATION-ON``` (```(let ((a 1.5) (b 2.5)) (+ a b))``` no more becomes ```(fx+ a b)``` when ```a``` and ```b``` are fixnums outside).

The parser curly-infix2prefix4racket.rkt produces the same code as the reader: the annotated code when the file has the pragma ```ANNOTATION-ON```, and never the ```type``` forms nor the pragmas. It also takes in account the postfix operators declared at the top level of the file.

The procedures and macros of the program are known by the infix parser of Scheme+ (with Scheme+ 18.0): while reading, the reader stores the procedures and macros defined in the file, the names declared with a type of procedure (```(type procedure? vector-map)```), the overloaded ones, and the variables declared with a type which is not a procedure. Between ```{ }``` ```(vector-map - v)``` is then a call of ```vector-map``` and no more ```(- vector-map v)```, ```(1 2 my-f)``` is ```(my-f 1 2)```, and ```(x 3 +)``` is ```(+ x 3)``` when ```x``` has the type ```flonum?```. These declarations and those of the postfix operators act only on the file where they are written.

Pragmas ```CARE-OF-QUOTES-ON``` and ```CARE-OF-QUOTES-OFF``` (with Scheme+ 18.0), by region like ```ANNOTATION-ON``` / ```ANNOTATION-OFF```. With ```CARE-OF-QUOTES-ON```, the state at the beginning of each file, the quotes are respected: a quoted list is data, and a quoted ```{ }``` is converted at its top level only, its ```( )``` stay as written whatever the number of operators (```'{(x + y) * z + 1}``` is ```(+ (* (x + y) z) 1)```, it was ```(+ (* (+ x y) z) 1)``` while ```'{(x + y) * z}``` was already ```(* (x + y) z)```), ```'{a}``` is ```a``` and ```'{a b}``` is ```(a b)```. ```CARE-OF-QUOTES-OFF``` opens a region for the symbolic computation: the quoted and quasiquoted lists are infix expressions at all levels, ```'(Bₖ · Bₖ₋₁ ⊕ Cₖ · (Bₖ ⊕ Bₖ₋₁))``` is ```(⊕ (· Bₖ Bₖ₋₁) (· Cₖ (⊕ Bₖ Bₖ₋₁)))```, and in a quasiquote the parts ```,…``` and ```,@…``` stay as written. The constant ```care-of-quote``` of the reader is no more used.

Strict SRFI-105 mode repaired: between ```BEGIN-STRICT-SRFI-105-REGION``` and ```END-STRICT-SRFI-105-REGION``` an expression that is not a simple infix one gives ```($nfx$ …)``` (```{a + b * c}``` was converted with the precedence, it is now ```($nfx$ a + b * c)```), a simple infix one gives ```(op a b …)``` also with ```if```, and the pragmas written in curly brackets ```{BEGIN-STRICT-SRFI-105-REGION}``` no more leave ```()``` in the code.

The banner displays also the version of Scheme+ and the author.

Quoted lists are data (with Scheme+ 18.0): inside ```{ }``` a quoted or quasiquoted list ```( )``` is no more parsed as infix or postfix (```'(x + y)``` stays ```(x + y)```, ```'(1 2 3 +)``` stays ```(1 2 3 +)```, and ```'(+ - * /)``` or ``` `(x + y ,z) ``` no more cause a parsing error). As in the original SRFI 105, in a quote or a quasiquote only the ```{ }``` are infix: ```'{x + y}``` is ```(+ x y)```, and an unquoted part written in infix uses curly brackets too, ``` `(a ,{y * 3}) ```. A symbolic formula is then written with ```'{ }```, for example ```'{{B1 · B0} ⊕ {C1 · {B1 ⊕ B0}}}``` is ```(⊕ (· B1 B0) (· C1 (⊕ B1 B0)))```.

The syntax quotes are data too: ```#'(...)```, ``` #`(...) ``` and ```(quote-syntax ...)``` are not parsed inside ```{ }``` and are not rewritten by the type annotation pass (```#'(a + b)``` stays ```(a + b)```, ```#'(+ 1 2)``` is not folded to ```3```). As with a quote, only the ```{ }``` inside them are infix: ```#'{a + b}``` is ```#'(+ a b)```.

**Changes of version 10.1:**

Updated code of pragmas to insert in source code to define strict SRFI-105 region parsing that are now:

```BEGIN-STRICT-SRFI-105-REGION```

```END-STRICT-SRFI-105-REGION```

They are no more between {  } , the update of code is because of a bug, the previous pragmas version where making a side-effect on generated source code by in serting a ```#<void>``` result causing some code to fails , for example Racket's contract where false because the returning type code was the ```#<void>``` instead of being what it should be.

Example of code:

```scheme
(require (rename-in racket/contract (-> C>)))

BEGIN-STRICT-SRFI-105-REGION
{positive-integer? C> (listof positive-integer-triplet?)}
END-STRICT-SRFI-105-REGION
```

where ```C>``` is in fact ```->```

Also now this simple code is working starting with Scheme+ version 10.4:

```scheme
{positive-integer? -> (listof positive-integer-triplet?)}
```



**New feature of version 10.0:**

Allow strict SRFI-105 compatibility that had been altered in previous versions.

This could be done by setting the srfi-strict flag in the library source code or simply in develloper code by using pragmas.

Pragmas to insert in source code to define strict SRFI-105 region parsing.

```{BEGIN-STRICT-SRFI-105-REGION}```

```{END-STRICT-SRFI-105-REGION}```

example:

```scheme
{BEGIN-STRICT-SRFI-105-REGION}
#<void>
#<eof>
{abs (3.7 + 1)}
(abs (3.7 + 1))
. . ../../../../../../racket/collects/racket/private/kw.rkt:1260:25: application: not a procedure;
  expected a procedure that can be applied to arguments
  given: 3.7

{END-STRICT-SRFI-105-REGION}
#<void>
#<eof>
{abs (3.7 + 1)}
($nfx$ abs (3.7 + 1))
4.7
```
