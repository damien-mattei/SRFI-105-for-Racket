1 Pragmas🔗

A pragma is a bare symbol written in the source code: it is recognized by the reader while it reads the file, not by the Racket compiler, and it does not remain in the code.

A pragma is written alone, or alone in curly brackets ({BEGIN-STRICT-SRFI-105-REGION}). It can be written inside a list (the body of the module form, of a procedure, ...) or at the top level of the file, before the module form, where it acts on the whole module. A pragma acts only on the file where it is written, not on the modules this file requires: each file starts in the state of the table.

1.1 Strict mode: using the reader as the original SRFI 105🔗

Between BEGIN-STRICT-SRFI-105-REGION and END-STRICT-SRFI-105-REGION the reader follows SRFI 105, as the original reader: {a} is a, {a b} is (a b), {a op b op c} with a single operator is (op a b c) (also with if), the () are not infix, and the other expressions are ($nfx$ …). As in SRFI 105, the neoteric expressions f(x), f{x} and x[i] are recognized only inside curly brackets, in both modes: outside, f(x) is read as the two data f and (x).

Racket defines neither $nfx$ (used for the expressions that are not simple infix) nor $bracket-apply$ (used for x[i]): SRFI 105 leaves them to the programmer. Define them yourself, or take them from Scheme+, where $nfx$ evaluates the expression with the precedence of the operators. A whole file in strict mode, as with the original reader:

#lang reader SRFI-105
BEGIN-STRICT-SRFI-105-REGION
(module m racket
  (require (only-in Scheme+ $nfx$ $bracket-apply$))
  (define (f x) {x * 2})
  (define v #(10 20 30))
  (display (list {2 + 3 * 4} {f(5) + v[1] * 2} '{a + b * c}))
  (newline))

displays (14 50 ($nfx$ a + b * c)).

At the REPL, type the pragma alone (or alone in curly brackets): the mode changes for the rest of the session.

1.2 Type annotation: ANNOTATION-ON and ANNOTATION-OFF🔗

The pragmas ANNOTATION-ON and ANNOTATION-OFF turn on or off, by region, the type annotation and inference pass of Scheme+ (see the section Type annotation and inference of the Scheme+ documentation): a pragma acts on the elements that follow it in the same list and on all that is nested in them, until the other pragma or the end of the list. The pass is off at the beginning of each file: a pragma acts only on the file where it is written, not on the modules this file requires. It can be written inside the module form or at the top level of the file (before the module form, it acts on the whole module).

1.3 Quoted lists: CARE-OF-QUOTES-ON and CARE-OF-QUOTES-OFF🔗

The pragmas CARE-OF-QUOTES-ON and CARE-OF-QUOTES-OFF act by region too, on the quoted lists (see the section Pragmas of the Scheme+ documentation): with CARE-OF-QUOTES-ON, the state at the beginning of each file, a quoted list is data and a quoted {} is converted at its top level only; CARE-OF-QUOTES-OFF opens a region for the symbolic computation, where the quoted and quasiquoted lists are infix expressions at all levels ('(x + y * z) is '(+ x (* y z))).

2 Converting a Scheme+ file into a Scheme file🔗

The command line tool src/curly-infix2prefix4racket.rkt of this package converts a Scheme+ file into the Racket code that the reader gives to the compiler, for example to debug it with the Racket tools (error line numbers, macro stepper, ...):

racket curly-infix2prefix4racket.rkt [--verbose] file+.rkt > file.rkt

The converted code is written on the standard output. When the Scheme+ file has the pragma ANNOTATION-ON, it is the annotated code, the same as the code compiled by the reader; it never contains the type forms nor the pragmas. With the option –verbose, the banner and the state of the type annotation are displayed on the error output. The Makefile of the Scheme+ examples uses this tool to generate the files of the parsed_files_directory directory.
